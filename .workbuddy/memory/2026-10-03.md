# 2026-10-03 工作日志

## 第三十次：全面复查"同步/下载总失败" + 修"只采到 8 条"根因

**用户诉求**：各个功能还是有问题，全面复查然后修复，总是同步不了和下载不了，弄个不会被风控的逻辑。

**全面复查结论（风控本质）**：
- 抖音 Argus 只门禁**非浏览器直连请求**（CLI 直连 API）与**页内注入式 XHR**（`bridgeFetchWindow`）。
  真实浏览器**自身页面加载 + CDP 拦截**拿到的请求（collectUserWorksViaBrowser reload 重放、
  collectAwemeDetailViaBrowser reload 重放）**不被风控**——这是唯一稳定通道。
- 因此"不会被风控的逻辑"= **所有数据来自真实浏览器 CDP 拦截**；页内 XHR / 直连仅作最后兜底（且 XHR 被 403 时会自动回退到 CDP 窗口，终点仍是真实浏览器）。
- 同步/下载链路**已经**是"API/XHR 失败 → CDP 兜底"，真正卡死的是下面这个 bug，不是风控策略本身。

**真正的元凶（实测）：采集窗口离屏 → 只采到首屏 8 条**。
- `collectUserWorksViaBrowser` 静默窗口用 `x:-32000,y:-32000`（离屏）。离屏窗口被 Chromium 视为
  occluded/hidden，**抖音首页 IntersectionObserver 懒加载不触发** → 只抓到首屏约 8 条就因
  idleRounds 提前停止。证据：每次 collect 日志都是 `ids=8`（post/like 都一样），而缓存有 2618 条。
  这直接导致"同步不全 / 下载不全 / 看着像失败"。
- 详情接口不受影响（请求在 loadURL/reload 时发出，不依赖懒加载），故详情走 XHR→CDP 窗口兜底即可。

**本次修复（已 node --check + py_compile 通过）**：
1. `main.js` `collectUserWorksViaBrowser`：在滚动采集循环前把离屏窗口**移回屏幕内**
   （`setPosition(60,60)` + `setOpacity(0)` + `setIgnoreMouseEvents(true)`，对用户不可见、不挡点击），
   让懒加载正常翻页，抓到**完整**作品列表。这是"不会被风控 + 采全"的关键。
2. `api_client.py`：桥端口缺失时由静默 `return None` 改为**明确 logger.warning**；新增
   `is_bridge_available()`。
3. `sync_service.py`：喜欢同步桥不可用时直接报"请先打开 DRaccoon 桌面端并保持登录"（不再抛 -502）。
4. `user_downloader.py`：下载入口加 `is_bridge_available()` 校验，桥不可用时明确报错（不再"已完成 0 项"）。
5. **撤回**了"详情改窗口优先"的改动：会破坏 `tests/test_detail_page_channel.py`（锁定页内 XHR 优先、不弹窗），
   且 XHR 403 后本来就回退 CDP 窗口，终点相同，改了无意义。

**生效前提（务必告知用户）**：DRaccoon 桌面端必须**运行且已登录抖音**（提供 Chromium 桥 + DOUZY_BRIDGE_PORT）。
