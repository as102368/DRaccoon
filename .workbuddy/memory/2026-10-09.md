## 第三十一次：参考 parse-video-py 修复"获取不到数据"——实测证伪无签名路径

**用户诉求**：参考 https://github.com/baige778/parse-video-py 修复获取不到各种数据的问题。

**该项目思路（两级降级）**：
1. 原生无签名 HTML 解析：GET `https://www.iesdouyin.com/share/video/{id}/`，正则取
   `window._ROUTER_DATA` → `loaderData['video_(id)/page'].videoInfoRes.item_list[0]`（图集 `note_(id)/page`），
   `video.play_addr.url_list[0]` 把 `playwm` 换 `play` 得无水印地址。
2. 失败则降级：**持久化登录态 Playwright 浏览器**兜底，拦截页面自己发出的 detail XHR（真浏览器自动签名）。
3. 作者已明确移除：假 `a_bogus` 签名（必 403）、Cookie 纯 HTTP 直连（因 `ArgusSecurity Uifid Not Found` 失效）。

**⚠️ 实测证伪（重要，勿再走此路）——本机带真实 Cookie 探测结果**：
| 探测目标 | 结果 |
|---|---|
| `iesdouyin.com/share/video/{id}/` | 302 → `www.douyin.com/video/{id}?previous_page=app_code_link`，返回 **72914 字节 JS VM 外壳**（`_$jsvmprt`），**无 `window._ROUTER_DATA`** |
| `iesdouyin.com/web/api/v2/aweme/iteminfo/?item_ids=` | 200 但 **body 长度 0**（端点已废弃） |
| `www.douyin.com/video/{id}` **带 Cookie** | 828KB 完整 SSR HTML，但 `play_addr`/`aweme_id`/`aweme_detail`/`item_list` **出现次数全为 0**；`RENDER_DATA` 仅 `{'app':...}`（209KB app 外壳） |

**结论**：抖音网页已改成 **JS VM 保护**，视频数据**不在 HTML 里**，必须由页面 JS 执行后发 XHR 才能拿到。
→ **所有"无签名/HTML 抓取/老接口"通道全部死亡；真实浏览器（CDP 拦截）是当前唯一可行路径。**
→ DRaccoon 现有架构（collectUserWorksViaBrowser / collectAwemeDetailViaBrowser 走 CDP）是**正确**的，不要再改回 HTML 抓取。
