# 2026-09-17 工作日志

## 阶段 C：修复页面通道异常（post 模式拉不到作品）— 第 18 次修复

**现象**：用户下载某用户主页（post 模式）报 `拉取作品列表失败：桌面端页面通道异常` / `获取不到啊`。

**根因**：post 模式的 `get_user_post` → `_request_json_gated` → `_fetch_via_page_bridge`（Electron 侧 `/v1/browser-fetch` 页面通道）。该通道在已加载 douyin.com 的隐藏窗口内注入 `window.fetch` / `XMLHttpRequest` / 直接导航来代发请求，但**抖音 SDK 不会给注入请求补 `x-secsdk-web-signature` / `a_bogus` 签名**（main.js:2556 注释已确认），因此所有 gated 端点（aweme/post、collects、mix、music、favorite）都被 Argus 确定性拒绝（403 且 body 含 `ArgusSecurityPlugin`，或请求整体失败返回 status 0 → 归类为 `argus_rejected` / `page_bridge_error`）。`post_strategy.collect_items` 原本在第 84 行对 gated 错误**直接 hard raise**，导致后文更可靠的 CDP 浏览器采集兜底（`_recover_user_post_with_browser` → `collect_user_post_ids_via_browser` → `_collect_via_electron_bridge` 拦截抖音自有签名响应）根本没机会执行。

**修复**（Python 侧，未改 main.js）：
1. `base_strategy.py`：新增 `_gated_error_message(page, context)` 返回文案或 None；`_raise_if_gated_error` 改为调用它。
2. `post_strategy.py`：`collect_items` 中把「gated 错误即 raise」改为「记录 `bridge_blocked` 并 `break` 跳出分页循环」，随后进入已有的浏览器兜底块（`_recover_user_post_with_browser`），走 CDP 拦截抖音自有签名请求这条可靠路径；若兜底仍为空且 `bridge_blocked`，抛出清晰错误（页面通道被 Argus 拦截 + 浏览器兜底也未取到）。

**验证**：`py_compile` 通过（base_strategy.py / post_strategy.py）。

**生效前提**：必须彻底退出 DRaccoon 托盘进程后重开（历史多次"还是不行"根因是老进程仍加载旧代码）。

**待确认/局限**：
- 本次仅修复 post 模式。collect / mix / music / favorite 模式仍走已失效的 `/v1/browser-fetch` 页面通道，需要各自的 CDP 采集器（导航到对应页面并拦截各自 API 响应）才能彻底修复 —— 列为后续任务。
- 需用户实测：post 模式现在应弹出可见的「DRaccoon 作品采集」窗口并通过 CDP 取到作品。若仍失败，排查采集窗口是否被关、是否出现验证码/登录页。
